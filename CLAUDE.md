# godogbg

The GNU Backgammon (gnubg 1.08.003) evaluation engine as a small,
self-contained C library, to be wrapped as a Godot GDExtension. Given a board
and dice it returns the best move, plus cube decisions and evaluations.
Targets: Linux x86_64 (done), Windows x86_64 via mingw-w64 (done), Android arm64 via
the NDK. All builds are done from a Debian 12 host.

## Layout

- `gnubg/`: the **unmodified** upstream release tarball. Never edit it. The
  build compiles only 17 files from it (listed in `GNUBG_SOURCES` in
  `CMakeLists.txt`).
- `port/config.h`: hand-written replacement for the autotools `config.h`.
  SIMD is chosen with the `GNUBG_SIMD_SSE2`/`_AVX`/`_NEON` definitions.
- `port/hooks.c`: functions the engine expects from the excluded app layer
  (`getPkgDataDir`, `PrintError`, `outputerrf`, `pkg_datadir`).
- `include/gnubg_api.h` and `src/gnubg_api.c`: the public C API (16 `gnubg_*`
  functions).
- `tools/gnubg_cli.c`: test driver and usage example.
- `data/`: runtime files shipped with the game: `gnubg.wd` (weights),
  `gnubg_os0.bd` and `gnubg_ts0.bd` (bearoff DBs), `met/Kazaross-XG2.xml`.
  These were generated by a normal gnubg build (`makeweights`, `makebearoff`).
- `docs/BUILDING.md`: build instructions per platform. Keep it updated as
  platforms are added.

## Build and verify (Linux)

```bash
cmake -S . -B build/linux-x86_64 && cmake --build build/linux-x86_64 -j
ldd build/linux-x86_64/libgnubg.so        # expect only libc, libm, libmvec
build/linux-x86_64/gnubg-cli data best 4HPwATDgc/ABMA 3 1
#   31: 8/5 6/5   ... equity +0.219        (world class, the default)
build/linux-x86_64/gnubg-cli data cube 2D2GAQaMZ+EANA
#   no double -0.922  double/take -1.855  double/pass +1.000
build/linux-x86_64/gnubg-cli data selfplay 42   # full game, about 2 s
```

`GNUBG_SKILL=0..7` selects the level (4 = expert 0-ply, 5 = world class).

**Reference binary:** a stock CLI-only gnubg build is in
`/home/danny/src/temp/gnubg-1.08.003`. Use it to check that numbers match
upstream. It defaults to Jacoby on, so turn that off for comparisons:

```bash
cd /home/danny/src/temp/gnubg-1.08.003
printf 'set player 0 human\nset player 1 human\nset jacoby off\nnew game\nset board 2D2GAQaMZ+EANA\neval\n' \
  | ./gnubg -t -q -r -P .
```

Linux results were verified identical to this reference: the same
probabilities, equities and cube numbers.

## Decisions and gotchas

- **config.h shadowing.** gnubg sources `#include "config.h"`, and the
  compiler searches the source file's own directory first. A `gnubg/config.h`
  left by `./configure` would silently replace `port/config.h`. CMake aborts
  if it exists.
- **`exit()` inside the engine.** `EvalInitialise()` exits if the weights
  fail to load, so `gnubg_init()` checks for `gnubg.wd`/`gnubg.weights`
  first. The SIMD CPU self-test can also exit (AVX) or install a `SIGILL`
  handler (NEON). The defaults are SSE2 on x86_64 and NEON on arm64, both
  ABI-guaranteed, built with `DISABLE_SIMD_TEST`. AVX is opt-in.
- **Single-threaded.** `USE_MULTITHREAD` is not defined, and `mtsupport.c`'s
  non-threaded branch sets up `td`. The API is not re-entrant.
- **Static glib.** CMake resolves `pkg-config --static` libraries to their
  `.a` files but keeps system libraries (`c m dl rt pthread log`) dynamic.
  Linking `libm.a` into a `.so` fails. The shared library uses
  `-Wl,--exclude-libs,ALL` and hidden visibility, so only `gnubg_*` is
  exported. Debian's `libglib-2.0.a` and `libpcre2-8.a` are PIC.
- **Board convention** (gnubg's TanBoard): `board[1]` is the player on roll
  and `board[0]` the opponent. Each side is indexed from its own home: index
  0..23 is points 1..24, and index 24 is the bar. Call `gnubg_swap_sides()`
  after each turn. Moves use `from` 1..25 (25 = bar) and `to` 0..24
  (0 = off). In `gnubg_match`, index or owner 1 is the player on roll.
- **Money defaults.** `gnubg_match_money()` / `NULL` set Jacoby **off** and
  beavers **off**. gnubg's own default has both on.
- **Cube mapping** in `gnubg_cube_action` mirrors the computer player in
  upstream `play.c`, except that "optional" doubles do not double.
- **Flags** follow upstream: `-O3 -ffast-math -DG_DISABLE_ASSERT`, plus
  `-mms-bitfields` on mingw.
- **Licence.** gnubg is GPL-3.0-or-later, so this repo is too, and so is any
  game that links it.

## Status and next steps

1. Done: Linux x86_64 shared and static library, CLI, docs.
2. Done: Windows x86_64 (mingw-w64). `scripts/build-glib-mingw.sh` builds
   a static glib 2.74.6 with meson (wraps for pcre2/libffi/zlib/proxy-libintl)
   into `build/deps/mingw-x86_64`, and
   `cmake/toolchains/mingw-w64-x86_64.cmake` points pkg-config there.
   `gnubg.dll` imports only Windows system DLLs. Under wine its best-move and
   cube output matches Linux. Self-play can differ between platforms on exact
   equity ties (msvcrt and glibc `qsort` order equal elements differently).
3. **Next: Android arm64-v8a (NDK).** Probably the easiest route is the same
   meson cross build as for Windows, with an NDK cross file. A shim is the
   alternative: the engine links 25 glib functions, mostly trivial, except
   `g_markup_*` (MET XML parser) and `g_mapped_file_*` (bearoff DBs).
4. Godot GDExtension wrapper (godot-cpp), kept separate from the C library.

## Working conventions

- The user installs system packages (`sudo` needs a password). Ask them to
  run the `apt install` commands.
- Keep `gnubg/` untouched. All adaptation goes in `port/`, `src/` and the
  CMake files.
- Verify against the reference binary after engine-affecting changes.
